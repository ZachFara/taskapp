# P2 Command and key registry   (ID: P2)   UI only, no cargo, no visuals

One registry feeds the command menu, the keyboard, the tooltips and the cheat sheet. You build the engine and the
contract, not the screens. You own: `ui/src/lib/commands/**`, `ui/src/lib/selection.svelte.ts`, and you replace
`ui/src/lib/keymap.ts` + its test (update its existing callers minimally so the app still works).

- `registry.ts`: `defineCommand({ id, label, icon, group, shortcut?: string | string[], noShortcutReason?: string,
  when?: (ctx) => boolean, run?: (ctx) => void | Promise<void>, page?: (ctx) => CommandPage, keywords?: string[] })`.
  A command has `run` or `page` (a nested list: e.g. "Set status" -> statuses). `ctx` = { route, selection (issue ids),
  focusedIssueId, openIssueId, api, navigate }. `listCommands(ctx)` returns those whose `when` passes, contextual
  (selection/open issue) first. `shortcutFor(id)`, `labelFor(id)` for tooltips; `groups()` for the cheat sheet.
- Self-registration: `defs/**/*.ts` loaded with `import.meta.glob('./defs/**/*.ts', { eager: true })`; ONE FILE PER
  COMMAND so parallel tasks never edit a shared list. Ship only a few defs yourself as examples and tests:
  `issue.create` (c), `palette.open` (mod+k, mod+p), `help.shortcuts` (?), `nav.search` (/). Other tasks add the rest.
- `keys.ts` engine, attached once at the app root: single keys, modifiers, sequences (`g g`, `g i`, `g p`), shift
  variants (`shift+j`), `G`, optional counts (`5 j`), a 1s sequence timeout, Esc cancels a pending sequence.
  HARD RULES, each with a test: (1) no shortcut fires while focus is in input, textarea, select or contenteditable
  (except `Escape` and `mod+` combos explicitly marked `global: true`); (2) the key that opens an input is never typed
  into it (today `c` opens quick-add and types "c": write the regression test first, watch it fail, fix);
  (3) IME composition is ignored; (4) a duplicate binding for the same key in the same `when` scope fails a test.
- `selection.svelte.ts`: focused row id, selected ids, range extend (shift+j/k), toggle (x), clear (Esc), select all in
  view; pure store with tests; views will bind to it later.
- Registry walk test: every registered command has a label, an icon id, and either a shortcut or `noShortcutReason`.
- Fuzzy matcher `match.ts` (subsequence scoring, label + keywords, recent items boost) with tests; no dependency.
- Document the contract in `ui/src/lib/commands/README.md` (how to add a command file, key syntax, scopes).
No palette UI, no cheat sheet UI, no tooltips: those are other tasks. No harness capture needed (say so).
