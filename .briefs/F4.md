# F4 Import from other tools   (ID: F4, migration: 0005_import.sql only if needed)

Goal: CSV import with column mapping, and a Linear import through its API. Both do a dry run first and write nothing until confirmed.

- New crate or module (your call; prefer `crates/core/src/import/` with `csv.rs`, `linear.rs`, `plan.rs`).
- Shared shape: source -> `ImportPlan` (what would be created: statuses, labels, projects, cycles, property defs,
  issues, relations, plus warnings and skipped rows with reasons) -> `apply(plan)` in ONE transaction, one history
  step label "Import N issues". Dry run = build and return the plan. Apply takes the plan (or a plan id/hash) so
  what is written is exactly what was shown.
- CSV: mapping from column name to: title, description, status, priority, project, labels (split on a separator),
  start date, due date, estimate, or "custom property <name>" (created as a property def if missing; infer type
  text/number/date/select conservatively, default text). Unmapped columns are ignored and listed. A guessed default
  mapping from header names is offered. Bad rows are skipped with row number and reason, never abort the file.
- Linear: GraphQL API, token passed in by the caller at call time (never stored, never logged, never written to a
  file). Map workflow states -> statuses (by category), labels, projects, cycles, relations, parent/sub-issues,
  estimate, due date, and custom fields if the API returns them. Paginate. Record the Linear identifier in the
  existing `import_log` so a second run does not duplicate.
  DO NOT call the real Linear API. Put the HTTP behind a small trait and test against recorded-shape fixtures you
  write by hand from Linear's public schema; say in the report that it was never run live.
- Expose: CLI `import csv <file> [--map col=field ...] [--apply]`, `import linear [--apply]` (token from env var
  LINEAR_API_KEY read at run time); MCP tools `import_csv_plan`, `import_linear_plan`, `import_apply`; commands
  dispatch + mock api for the CSV path. No screen.
- Tests: CSV happy path; header guess; bad rows skipped; custom property created; dry run writes nothing (row counts
  equal before/after); apply equals plan; re-import does not duplicate; Linear fixture maps states, labels,
  relations, sub-issues; token never appears in Debug output or errors.
