# P5 Undo covers everything   (ID: P5)   Rust core only; touches NO file under ui/

Today undo (crates/core/src/undo.rs, history.rs) covers issue edits, bulk edits, create and archive, and REFUSES changes
to labels, comments, projects, milestones, cycles, property definitions, relations, issue-label assignment, statuses,
views, pins, templates, icons/colours and imports that create any of those, because history records too little.
Make every change undoable and redoable as one step.
- Record enough in `changes` to reverse each kind: for deletes, a full snapshot of the row and its links (JSON) so undo
  restores the same id and links; for creates, the id so undo deletes (or archives where hard delete is unsafe); for
  link tables (issue_labels, relations, pins), the pair. Migration `0006_undo_snapshots.sql` if columns are needed.
- Cover: labels (CRUD + assign/unassign), comments, projects, milestones, cycles, property defs (+ values on issues when a
  def is deleted), relations, statuses (incl. delete-with-move: undo moves the issues back), views, pins, templates,
  icon/colour changes, work blocks, settings, and a whole import step (issues plus everything it created).
- Keep the rules: one step per command call; conflict refusal if the current value differs from the step's new value;
  all-or-nothing in one BEGIN IMMEDIATE transaction; undo/redo are never steps. If one kind truly cannot be reversed
  safely, refuse it clearly and list it; the target is zero refusals.
- Fix the known risk: a step id allocated before a first write that rolls back must not leave the redo stack uncleared.
- Tests, each watched failing first: one per entity kind (create, edit, delete+restore with links), bulk label assign over
  3 issues as one step, status delete-with-move round trip, import that creates a label and a project undone in one
  step, redo for each, conflict refusal still works. Update the tests that assert "not covered" refusals.
- `.sqlx` regenerated; MCP/CLI undo tests still pass.
