## Shared shapes (Rust snake_case; TS as the generator emits)
- Issue gains `points: Option<f64>` (>= 0, up to one decimal); patches and BulkPatch carry it (`Clearable`); `FieldRef::Points` for display, sort, group and filter; templates and CSV/Linear import map it (Linear `estimate` -> points when the workspace uses points).
- Settings (existing settings api): `estimation` = "none" | "points" | "time" | "both" (default "both"), `point_scale` = "fibonacci" (0,1,2,3,5,8,13,21) | "linear" (1-10) | "powers" (1,2,4,8,16) | "tshirt" (XS=1,S=2,M=3,L=5,XL=8) (default fibonacci). "none"/"time" hide points everywhere.
- Quick add grammar: `3pt`, `0.5pt` (and `pt3`) sets points; mock parser identical.
- `insights_progress(scope, measure, from?, to?) -> ProgressSeries` where `scope` = `{ Project: id } | { Cycle: id } | { View: id }`, `measure` = "points" | "count" | "time", and `ProgressSeries { days: [{ date, scope, started, completed }], measure, from, to }`: for each local day (workspace zone) the total of the measure over issues in scope (`scope`), over those whose status category was started or completed (`started`), and completed (`completed`), RECONSTRUCTED FROM THE CHANGE HISTORY (status changes and points/estimate changes as of that day; membership = the issues in scope now, plus creation date so an issue counts only from the day it existed). Default range: project start..target (or first..last change), cycle start..end, view = last 30 days.
- `insights_velocity(scope, measure, periods) -> [{ start, end, label, completed }]`: completed per cycle when cycles exist, else per week.
