# F2 Issue templates   (ID: F2, migration: 0003_templates.sql)

Goal: saved templates that prefill an issue's fields, custom properties and sub-issues (examples: "Bug", "Research idea", "Trip").

- Table `issue_templates`: id, name (unique), slug (unique, for `/bug`), `icon` TEXT NULL, `color` TEXT NULL (plain
  nullable columns; another task defines what values mean), a JSON body holding title prefix, description, status,
  priority, project, labels, estimate, properties, and a list of sub-issue titles (each may carry the same fields).
- Core: create, list, get, update, delete a template; `create_issue_from_template(template, overrides)` creates the
  issue and its sub-issues in one transaction. References in the body that no longer exist (deleted label, project)
  are skipped and reported in the result, not an error.
- Quick-add: `/slug` at the start of quick-add text picks the template; the rest of the text is parsed as usual and
  overrides the template (see crates/core/src/quickadd.rs). Unknown `/slug` is an error that lists the known slugs.
- Expose: commands dispatch, Tauri, MCP tools (list/create/update/delete/apply), CLI `template ...`, mock api
  (the mock must apply templates the same way, including quick-add `/slug`).
- Tests: CRUD; apply with sub-issues; overrides win; missing references skipped and reported; quick-add `/bug Fix login p1`;
  unknown slug error.
- Seed no personal templates. The seed/dev data may include "Bug" and "Research idea".
