F1 CRITICAL: Esc with nothing open calls history.back() and LEAVES THE APP (the page went to about:blank). Rule: Esc closes the top overlay, else clears the selection, else on /issue/:key goes to the list it came from; on any top-level route Esc does nothing. Never history.back() past the app's first entry. Walk: press Esc 3 times on /view/1 -> still on /view/1 with the list visible.
F2 CRITICAL: page commands opened by key (s, p, l, d, shift+d, e, m, shift+c, a, r ...) open the palette ROOT, not their page. `s` must open "Set status" with the statuses listed and the query empty; typing "prog" + Enter sets In Progress on the whole selection; `d` then "next fri" shows the parsed date as the first row and Enter sets it. Walk covers s (with 2 rows selected, then both rows show the new status, then `u` undoes both) and d.
F3 The palette root and the right-click menu list EVERY command regardless of where you are (calendar "Month view", table "Edit cell" on the list view; the right-click menu is ~40 items and runs off the top of the screen), all under the contextual header. `listCommands(ctx)` must return only commands whose scope/when match the current route, layout and state. Root order: actions on the selection/open issue (ONLY issue actions) first, then navigation, then view actions, then create, then settings/help. The context menu shows only issue actions for that row, grouped (status, priority, labels, project, cycle, dates, estimate | relations, parent, duplicate, copy | pin, archive), at most ~16 items, and never overflows the viewport. Walk: palette root on a list contains no calendar/table/timeline command; right-click menu has <= 18 items and its top is >= 0.
F4 Layout is unknown to commands: on the board `l` opened the palette instead of moving to the next column. App's ctx must expose `layout` (list|board|table|timeline|calendar|null) and each layout must call `selection.setLayout(...)` on mount: report the exact one-line change each view file needs (you do not own the view files) AND set it from ViewPage's chosen layout through a prop/effect you can reach from App/ctx if possible (route /view/:id/:layout and the saved view's layout are both known to the stores). Table commands get `scope: 'table'`; delete defs/rulings.ts. j/k must work in table too via the selection store (no double move).
F5 Enter on a focused row navigates to the full page /issue/KEY. It must open the SIDE PANEL over the current view (panel shows the issue, list stays, focus stays in the list for j/k so the panel follows); "Open full page" is a separate command (mod+enter) and the panel has an expand button. Walk: Enter -> URL still /view/1, panel visible, j moves and the panel shows the next issue, Esc closes the panel.
F6 The "Created ABC-n" toast shows an empty dark box where the Undo button is (invisible label). Toast actions must be readable on the toast background (design-system token for on-dark button), with "Undo" and "Open". `u` with nothing to undo shows a quiet "Nothing to undo", not the raw "invalid: nothing to undo".

Keep ONE command per action that works on the selection, the focused row and the open issue alike; merge groups; the registry walk test must fail on two commands with the same label in the same scope.
