# R3 UI flows, keys, command menu, selection, accessibility   (ID: R3)
Area: ui/src/lib/commands/**, ui/src/lib/selection.svelte.ts, ui/src/app/**, ui/src/components/{CommandPalette,CheatSheet,QuickAdd,UndoToast,IssueDetail,Setup}.svelte, ui/harness/walk.test.ts.
Method: drive the real UI in a headless browser (Playwright is installed: see ui/harness/walk.test.ts and <workspace>/taskapp/.scratch/walk3/walk3.ts for how; start Vite in mock mode on a free port: `VITE_API_MODE=mock pnpm -C ui exec vite --port <free> --strictPort`), take screenshots into your scratch folder and LOOK at them.
Check every line of the owner's spec for keys and the menu: j/k, gg, G, h/l (board columns), Enter opens the side panel, Esc closes or steps back and never leaves the app, / search, counts (5 j), x toggle, shift+j/k extend, then s status, p priority, l labels (list/table/detail) and shift+l, d due, e estimate, m move project, c create, g-prefixed jumps (g i, g v, g p, g t, g s), ? cheat sheet generated from the registry, tooltips with the shortcut on every button, Cmd+K and Cmd+P, fuzzy search over commands, issues, views, projects, cycles, labels, settings, recents; contextual actions first when issues are selected or open; nested pages and Backspace on an empty query goes back; every command shows its shortcut; EVERY mouse action reachable from the menu (walk each screen, list any button whose action has no command). HARD RULE: no shortcut fires while focus is in an input, textarea, select or contenteditable, and the key that opens an input is never typed into it: test this on every input you can reach (quick add, palette, filters, rename, description, comment, settings fields, display search, new view dialog, setup). Bulk actions over a selection are ONE undo step (check 5 different actions). Focus management: after closing each overlay focus returns to where it was; tab order; visible focus ring; every icon-only button has an accessible name; the cheat sheet, palette and dialogs trap focus and close on Esc; reduced-motion respected. Multi-select with click, cmd-click, shift-click, select all. First-run setup flow from a fresh mock (setup not done). Key clashes the clash test might miss (two commands active together in real use).
